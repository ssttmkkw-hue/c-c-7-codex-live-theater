# Round 3 upgrade plan

## 中文摘要

这一轮优先让演员对台词和导演指令作出清晰可见的反应。第二轮拉近了镜头，观众更容易认出演员和发言者，但常规对白仍反复摆臂，听者缺少有节奏的反应，“放慢”在站定时也难以辨认。先修复语音尚未开始时调速可能截断台词、重复指令可能再次插入结尾的问题，同时保住第一拍立即开演的路径。随后加入有起落的动作、听者反应和明确的舞台调度。余量用于站台布景、标签避让和少量解析修正。默认继续使用免费的本地解析器，并分别测量字幕更新、首个可见舞台帧和语音起播。

## Bugs and regression risks

| Area | Finding |
|---|---|
| Startup | `localParser()` splits the entire input and scans for script syntax before yielding. `submit()` also rebuilds the cast before it consumes the first beat. Large pasted scripts and slow rendering devices can expose costs the short Hamlet measurement misses. [parser.js](/workspace/c-c-7-codex-live-theater/src/parser.js:128) · [director.js](/workspace/c-c-7-codex-live-theater/src/director.js:33) |
| Speech and tempo | A tempo note before `utterance.onstart` replaces the delivery via `deliver(false, ...)` while leaving the queued utterance alive. Its callbacks then fail the delivery identity check, and the replacement timer can cut it off. Pause also computes remaining time from the estimated duration even after speech has switched to the watchdog timer. [director.js](/workspace/c-c-7-codex-live-theater/src/director.js:127) · [director.js](/workspace/c-c-7-codex-live-theater/src/director.js:162) · [director.js](/workspace/c-c-7-codex-live-theater/src/director.js:206) |
| Directing | `/end\|finale/` matches ordinary words such as “send.” A second ending note during the alternate beat can insert another finale because `next()` checks `ending` before `alternatePlayed`. An ending queued on an actorless direction can also leave the stage’s queued-light flag set when `perform()` returns early. [director.js](/workspace/c-c-7-codex-live-theater/src/director.js:91) · [director.js](/workspace/c-c-7-codex-live-theater/src/director.js:206) · [stage.js](/workspace/c-c-7-codex-live-theater/src/stage.js:333) |
| Blocking and layout | Script marks alternate between two horizontal positions, even for larger casts. The gait is distance-driven in actor-local space, so a turning or settling actor can still slide at the contact foot. Projected labels have clipping checks and no collision handling. At phone widths, the one-column layout puts the directing desk below playback and the request form, so sending a note can take the stage out of view. [parser.js](/workspace/c-c-7-codex-live-theater/src/parser.js:38) · [stage.js](/workspace/c-c-7-codex-live-theater/src/stage.js:377) · [style.css](/workspace/c-c-7-codex-live-theater/src/style.css:335) |
| Script interpretation | `named` accepts `Location: a train station` as dialogue. Named action subjects usually have one word, while gaze targets capture only one word. A cue such as `[Mara Vale turns to Eli Stone.]` can therefore miss both cast names. The stage also creates meshes and labels as names arrive, so larger scripts can add rendering work during playback. [parser.js](/workspace/c-c-7-codex-live-theater/src/parser.js:22) · [parser.js](/workspace/c-c-7-codex-live-theater/src/parser.js:48) · [stage.js](/workspace/c-c-7-codex-live-theater/src/stage.js:314) |

## One implementation pass

### P0 — Preserve startup and fix live delivery

- Keep `Director.submit()` → `next()` starting beat index `0` on its arrival. In `deliver()`, `pause()`, `setSound()`, and `direct()`, track whether speech is queued, speaking, or finished and which deadline owns beat advancement. Rescale timer-driven beats immediately. Keep the current utterance intact and apply the new speech rate to the next utterance. Keep the stage response immediate. Verify that late callbacks from a previous beat, replay, or submission cannot advance the active scene.
- Match supported director commands as words or phrases. In `next()` and `perform()`, make the finale transition happen once per run, clear its queued cue when the finale starts, and handle a request during the last original beat, during pause, and during the finale itself.
- Recheck cold and warm submissions with sound off and on. Record time from submit to beat arrival, first surtitle mutation, first visible acting frame, and browser speech start where available. Require beat 1 to start with `parseDoneAt === null` on the streamed samples. Target tens of milliseconds for the first surtitle and visible response on a normal desktop, with both well under one second on the tested slower setup. Report speech onset separately because the browser voice controls it. Include a long pasted script in the startup check.

### P1 — Make directing legible with the sound muted and the desk out of view

- In `TheaterStage.perform()`, `update()`, and `pose()`, give each beat a preparation, one readable accent, and a settle. Choose a small set of silhouettes using the existing `emotion`, `gesture`, and `lookAt` fields. Give the addressed listener a delayed look, recoil, or lean keyed to that accent. For speech-enabled playback, use available start and end events to gate mouth movement. Use an estimated speaking interval for muted playback and voices with incomplete events.
- Give **Angrier** a braced advance or planted point and a timed listener recoil, with room between silhouettes. Give **Slower** a visibly longer hold and release even when both actors are stationary. For **Change ending**, start the cue on the stage when queued, then give the actors separate center marks, a shared light, and a held final tableau when the replacement beat arrives. Preserve the frozen pose on pause and check that resume continues it. Review short muted clips at 390, 1280, and 1920 pixels with the sidebar and cue text covered. Each direction should be identifiable from the scene itself.

### P2 — Improve scene and label readability if P0 and P1 pass

- Add one lightweight station look. Let `ideaBeats()` attach a preset to the first station beat and have `buildHouse()` switch a small set of resident scenic elements, such as a platform sign and canopy. Keep the stage, camera, and avatar fixed. Check that switching the preset introduces no visible first-beat hitch.
- In `update()` and `.cast-label`, reserve space for the active speaker first. Move the addressed actor’s label into a nearby clear slot or hide it when space runs out. Reserve the HUD edges and test long names, close blocking, and a three-person script. Fix multiword subject and gaze matching against cast names known so far in `scriptBeats()` without adding a full-script cast scan. At phone widths, check that a viewer can send a note and still see the response. If the existing scroll distance prevents that, bring the existing quick controls closer to playback.

## Must not break

- `npm run dev`, `npm run build`, and static hosting under the GitHub Pages repository path.
- `window.__theater.startSample`, `submit`, `direct`, `getState`, `pause`, `replay`, and `setSound`. Preserve the state fields and the `submit` and `startSample` promises that resolve when parsing finishes.
- The three samples, free-text ideas, pasted dialogue, and silent stage directions. Preserve immediate first-beat playback, cancellation on a new submission, and replay from the original input with fresh direction.
- Surtitles, keyboard controls, muted and unavailable-speech playback, and the text fallback when WebGL is unavailable. Keep stage size stable as directing feedback appears.
- Local parsing on the default path with no credentials or paid API calls. Keep keys, tokens, and `.env` files out of the public repository.

## Skip this pass

Skip provider integration, a general-purpose story generator, new character assets, full lip sync, world-space foot locking, a renderer rewrite, and a broad CSS redesign. Defer additional sets until the station preset proves it can switch without delaying the first visible beat. Deployment is outside this review.

## Implementation brief

Start from `682c75f`. Fix delivery ownership and one-shot finale handling in `src/director.js`, preserving the async first-beat handoff and the public debug hook. Then use the existing rigs in `src/stage.js` to replace repeated speech gestures with timed accents and listener reactions, and make Angrier, Slower, and Change ending readable in muted playback with the desk hidden. Verify first-beat timing, stale callback handling, and the mobile stage view before spending remaining time on the station preset, label placement, and multiword script cues. Finish with a production build and report timings for the DOM, visible stage response, and available browser speech separately.
